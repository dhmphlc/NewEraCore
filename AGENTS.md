This repository is **NewEraCore**, a PaperMC/Spigot core plugin for the New Era server.

## Architecture

**Entry point**: `NewEraCore extends JavaPlugin` (`com.edysmajler.neweracore`). Bukkit/Paper calls `onEnable()` and `onDisable()` during the plugin lifecycle. `onEnable()` loads and validates `config.yml`, then opens the SQLite-backed data store and starts its auto-flush task; `getPluginConfig()` and `getStore()` expose both to feature code. In `plugin.yml`, `${PACKAGE}.${NAME}` identifies the main class. The `processResources` task fills these placeholders at build time from `group` in `build.gradle.kts` and `rootProject.name` in `settings.gradle.kts`, so the class name must stay equal to `rootProject.name`.

**JAR packaging**: The standard `jar` task is disabled, and `shadowJar` is the sole output. It shades CommandAPI and relocates it to `<group>.commandapi`. CommandAPI is excluded from `minimize()` because it loads classes through reflection. `assemble` depends on `shadowJar`.

**cw-commons dependency**: [cw-commons](https://github.com/CrimsonWarpedcraft/cw-commons) provides `Command`/`BaseCommand` for command registration, `Config`/`BukkitConfigManagerBuilder` for YAML loading and Jakarta validation, and `BukkitDataStoreBuilder`/`Repository`/`PlayerDataManager` for persistent player data. These classes are not defined locally. The project consumes cw-commons from JitPack as `com.github.CrimsonWarpedcraft:cw-commons`. `build.gradle.kts` pins a tagged release, such as `v0.3.0`, instead of the unstable `main-SNAPSHOT`. Update that tag deliberately.

Jackson and Hibernate Validator remain direct dependencies because `PluginConfig` uses their `@JsonProperty` and `@NotBlank` annotations. cw-commons exposes these libraries as transitive, unbundled `api` dependencies so each consumer can shade and relocate its own copy without classloader conflicts. The direct declarations are redundant for dependency resolution, but they prevent this project from relying on another project's transitive exposure choices.

**World corruption engine** (`world/`): `WorldEngine` listens for `ChunkLoadEvent` and corrupts each chunk exactly once. Two gates enforce that: `isNewChunk()` limits work to freshly generated terrain, and `ChunkMarker` stamps `ChunkMarker.ENGINE_VERSION` into the chunk's persistent data container, which persists in the region file. The marker is written *before* the pipeline runs, so a failing processor cannot leave the chunk eligible for a second, compounding pass. Raising `ENGINE_VERSION` is the deliberate way to reprocess existing chunks.

The theme is an ashen nuclear winter, and two principles are load-bearing. Both came from shipped versions that looked *griefed* rather than ruined:

1. **Ash falls on everything; only depth varies.** Gating ground changes behind a coverage threshold leaves an intact world with altered blocks scattered through it — the griefer pattern, unfixable by tuning. `AshMantle` covers essentially all ground, and the level decides depth. `CorruptionProfile.DUSTING` enforces this in code: even the calmest end of the recovered band blends from a real ashfall, never from pristine, so no chunk anywhere is left vanilla.
2. **Whole shapes, not block edits.** Never thin a canopy. `DeadTrees` removes *all* leaves outside living groves and rebuilds a dead silhouette — charred basalt trunk, branch stubs, sometimes snapped or collapsed with the trunk laid in the ash. A vanilla tree shape with holes in it is the clearest griefing signature in the game. Wood that is not a standing trunk — the generator's fallen trees, a big oak's branch logs — is charred *in place* by `DeadTrees.charStrayWood`, orientation preserved, because fresh timber in a burnt landscape is the painted-on look in reverse; `TreeScan` only counts upright logs as trunk bases so a fallen run is never mistaken for a row of one-block trees.

A corollary: placement is terrain-coupled. `TerrainProbe` (`world/terrain/`) supplies slope, relief, and water proximity, so ash drifts into hollows and strips off steep faces. Damage that ignores the landform reads as painted on. Edge columns treat themselves as flat rather than reading across a chunk border.

Placement never comes from a per-block dice roll. Coherent OpenSimplex noise (`world/noise/`) decides where things go; `NoiseFields` holds five independently salted fields (corruption, patch, blight, impact, detail) built once per world and cached by `WorldEngine`. `NoiseField` calibrates itself so **thresholds are percentiles** — an early version set thresholds above 0.8 on a bell-shaped field and generated exactly zero craters. `detail-scale` must stay well above ~12 or materials alternate block by block and the ground reads as confetti. The seeded `Random` is only for texture inside an already chosen area.

`CorruptionZone` (`world/corruption/`) assigns a `CorruptionLevel` (`RECOVERED`, `SCARRED`, `DEVASTATED`) from the corruption field at the chunk centre, plus an intensity that blends the `CorruptionProfile` towards the level below so boundaries do not step. It is resolved once per chunk by `WorldEngine` and read through `ChunkContext.level()`/`profile()`/`intensity()`; no pass samples the large-scale field for itself, because two systems doing that in the same valley contradict each other.

**Scattered structures** (`world/structures/`): premade wrecks and ruins dropped into the world as whole shapes — the crashed fighter jet first, with `Car`, `Bunker`, etc. to follow. Sites live on a coarse hashed grid in world coordinates (`StructureSites`, same pattern as `CraterSites`): a pure function of the seed, so every chunk agrees on where a site is, what stands on it (`StructureManager` weighted draw), and which way it faces, without loading anything — and `/nec locate <kind>` can answer about terrain that has never generated. A candidate cell whose drawn structure refuses the ground (`StructureDefinition.suits`, via `LandLookup`) holds nothing; the draw is never retried, because a retry would make a site's identity depend on the ground test and every refinement of that test would silently move every structure.

Placement is the deliberate exception to slice-per-chunk rendering: a structure is a discrete silhouette, and a silhouette assembled from independent slices is one bug away from a seam. `StructurePlacer` treats each chunk of the footprint as a trigger — when the last one generates (`World.isChunkGenerated` over the footprint), the whole structure is built at once by `StructureDefinition.place` through `StructureField`, a world-coordinate writer with the same physics-off and clear-what-was-perched duties as `ChunkContext`. This is safe precisely because every footprint chunk already exists: cross-border writes load, never generate. `StructureMarker` stamps the site's centre chunk PDC *before* building (mark-first, like the engine), which settles the race when two footprint chunks arrive in the same tick and survives restarts.

Two invariants are tested in `StructureSitesTest` because their failures are silent: the candidate window is **derived from the registry's largest radius** (`StructureManager.maxRadius`), and every chunk a footprint touches must see the site — a chunk that misses it may be the last to generate, and then nothing ever places. `FighterJet` shows the intended anatomy: terrain → skid trench (hugs each column's ground, it is a mark *on* the terrain) → crater (cut to one reference plane from the impact point's ground, it is the terrain giving way — with fill capped like earthworks, since a plinth reads as a bug where a gap reads as subsidence) → hull (rasterised by inverse-transforming world columns into the jet's own axes, hole-free at any heading) → debris → loot chest. Variants from the site seed change the silhouette whole (snapped wing thrown clear, broken spine, stub tail), never punch holes in it. `SchematicStructure` is the drop-in path: `.nbt` files in `plugins/NewEraCore/structures/` join the scatter under their filename, rotated per site and placed at slightly under full integrity (containers ride out the roll, so the loot chest survives). It places block-by-block from the palette rather than via `Structure.place`, because a structure file records air as real blocks and vanilla placement carves the whole bounding box out of the terrain — air and structure void are skipped so the world shows through. The seat anchors on the model's lowest *built* layer, not its bounding box, and the vegetation over the footprint is cleared so nothing grows through a model. Its other subtlety is the per-rotation origin offset, since a structure rotates around its origin corner. A file named `<name>.crash.nbt` is wrapped in `CrashedSchematic`, which reuses `CrashScars` — the trench/crater/debris/smoke shared with `FighterJet` — sizes the crater from the model, and seats it on the crater floor; crash models are saved nose-east (+x). Per-template tuning lives in `structures.templates` in config.yml (`TemplateConfig`, keyed by id, built-ins included): `enabled`, `crash` (overrides the filename convention), `weight`, and `destruction` — one factor scaling crater, trench, debris, and smoke together, so the parts of a mess can never disagree about how hard the landing was. Master copies of the `.nbt` files live in `structures/` in this repo, because the test-server refresh wipes `plugins/NewEraCore/`.

**Structure loot** (`world/structures/loot/`): the plugin's own take on the vanilla loot-table shape — tables of pools, each pool rolling a count and drawing weighted entries — rather than `org.bukkit.loot.LootTable`, because Bukkit tables resolve by namespaced key from the datapack registry: custom tables would need a datapack shipped beside the JAR, and an unregistered table set on a chest dies silently with the chunk save. The layering is the `LandLookup` pattern again: everything that *decides* (`LootTable`/`LootPool`/`LootEntry` rolling into plain `ItemSpec`s) is pure and unit-tested; `LootStocker` alone touches Bukkit, turning specs into items (wear via `Damageable`, rare enchants via `ItemFactory.enchantWithLevels` — a `book` becomes an enchanted book, like vanilla) and scattering them into shuffled slots, because slot-zero-packed loot is the machine-filled look. All rolls come off `StructureField.random()`, so a site's loot is as fixed as its silhouette. Three tables ship built in (`military`, `civilian`, `hardware` in `LootTables`); config tables under `structures.loot` join them, replacing whole on an id clash — never merging, so a chest's possibilities are always readable from one place. A template picks its table by `loot:` in `TemplateConfig`, defaulting by convention: crash → `military`, plain → `civilian`, `none` disables. In a saved model an *empty* container is the loot marker and rolls fresh per placement; a container saved with items keeps exactly those, because hand-stocked contents are the builder's explicit word. Pools use weighted `nothing` entries (vanilla's `minecraft:empty`) so rarity reads directly off the entry list, and parsing is forgiving like schematic loading: an unknown material costs one entry and a log line, never the enable.

**Ruined towns** (`world/towns/`): clusters of collapsed houses on a seeded grid — `TownSites` is the `StructureSites` pattern on its own grid, nodes needing `LandLookup` land, `/nec locate town` answering over ungenerated terrain. Each town knows its *street headings*: unit vectors toward its nearest neighbouring towns within `MAX_SPAN_CELLS`, which `TownPlacer` lines the house rows along, doors inward — a town is a street with buildings on it, where buildings around a point are a camp. This system once paved actual roads (highways with centre lines and poles) and strewed cars along them; **both were removed by decision — they read as clutter** — and only the street directions survive. `ChunkContext.reserve` remains as the seam for any future built surface the mantle must dust but not repave. Towns place whole through `StructureField` (seed-only constructor) with the mark-first discipline via `PlacedMarker` (coordinate-carrying PDC keys), self-completing footprint stragglers like `StructurePlacer`. `RuinedHouse` draws ruin as a *gradient* — walls collapse toward one failed corner, roofs simply gone — because uniform random holes are the griefed pattern in miniature; every house tests its **whole footprint** for water, not just its centre. Cupboards stock from the built-in `civilian` table through the registry, so a config redefinition retunes towns too. `TownSitesTest` guards the footprint-window invariant (every chunk a town touches must see it), whose failure mode is a town that silently never places.

**World planner and world plans** (`plan/`, `world/plan/`, `src/planner/`): a designed world, not only a generated one. The split is forced by one boundary: everything the engine invents is a pure function of the seed and can be recomputed anywhere, but height, biome and water are *Mojang's* generator and need a real world. So `/nec export` samples a square into a `WorldSnapshot` (height, water depth, `TerrainClass`, the engine's own land/rugged flags, corruption and impact percentiles per sample, plus the resolved site list) and the standalone planner reads it. `WorldQuery` is the seam the planner asked for: the wiring of noise fields, corruption zones and all three siting systems behind coordinate questions, holding no `World` so it answers about terrain that has never generated — and `WorldQueryTest` asserts its answers *equal* the systems it wraps, because a wiring mistake there would plan towns where the plugin will not build them. Sites are exported rather than recomputed for a specific reason: each structure answers `suits` its own way, so a planner reproducing the grid arithmetic would have to reproduce every one of those answers and would drift the first time one was refined. `/nec export` **refuses to run while the engine is enabled** — a scan's chunks are only new once, so exporting from a live world either bakes corruption into a map meant to read as untouched terrain or leaves tens of thousands of chunks permanently vanilla. `SnapshotTerrain` is `TerrainProbe`'s counterpart over a saved raster (slope, relief, enclosure, valley, distance to water); `LocationType.rate` judges a position for a type and is **advisory only**, because a builder that refuses a site on arrival, after the plan was made around it, is the failure mode. The planner (`src/planner/`, a source set rather than a subproject so it compiles against main's output and its formats can never drift) draws shaded relief rather than a height ramp — a ramp cannot show a valley — and invents nothing: no automatic civilisation layer, no generated network. That shipped once and read as clutter.

`WorldPlanBook` reads a plan per world (`plans/<world>.json`, else `plans/world-plan.json`) and **refuses one whose seed does not match**, loudly: the file is still perfectly valid, so applying it would put every town on terrain nobody looked at with nothing in the log to say why. `PlanSites` translates a planned location into the site records the shipped placers already take — a `TownSite` (its streets being the plan's *roads*, which is a better statement of the same thing than a seeded town's guess at its neighbours) or a `StructureSite` whose footprint radius comes from the definition, never the designer, because only the definition knows how far its silhouette reaches. `PlannedPlacer` then applies the same discipline as both seeded placers (footprint completion budget, mark-first via `PlacedMarker`, self-completing stragglers), and `WorldEngine` filters seeded sites out of planned ground by `plan.clearance` — a procedural town beside a designed one stops the designed one reading as deliberate. Two subtleties are load-bearing. A planned type with **no builder places nothing and says so once**, rather than approximating a hospital with whichever wreck was registered, which would put a lie on ground a designer picked on purpose. And `PlannedPlacer.sweep`, called from `onEnable` and on `WorldLoadEvent`, exists because the chunk trigger cannot cover the one place a designer is most likely to build: a fresh world's spawn area generates *before* plugins enable, so those chunks are never new — and the planner centres its map on 0,0. It is also what lets a plan be applied to a world that already exists. `ShippedConfigTest` parses the real `config.yml` because no other test did: constructing config objects cannot notice a mistyped key or a documented value its own validation rejects, and that failure surfaces as a plugin that will not enable.

`Vegetation` (`world/`) holds every rule about plants, because each one was learned from a shipped artefact. A plant can be two blocks tall and the snapshot height map counts neither half, so a pass must look `Vegetation.REACH` above the surface or it strips a sunflower's stem and leaves the head. Grass is removed everywhere outside living groves; whether a grove keeps its *floor* depends on the biome group's `groveFloorsStayGreen()`: in dense forest (forest/taiga/jungle) the grove floor stays completely untouched — grass, soil, a dusting only on the rim — because a living stand over a swept-bare floor was its own artefact, while open country keeps the flag off, because the grove test is a noise threshold, not a tree count, and green floors in plains read as half a vanilla world. `ChunkContext.isLivingGrove` is the one definition of membership the tree, undergrowth, and mantle passes all share. The newer ground plants — leaf litter, bushes, dry grasses, wildflowers — are named in `Vegetation.UNDERGROWTH` outright, because none sit in the block tags the engine otherwise trusts: an unlisted plant is invisible to every pass, and the mantle repaves the ground under it with a dirt path while the plant floats on a block that cannot hold it. Leaf litter is cleared rather than converted to a dead bush — litter comes in patches dense enough that converting a share would carpet the floor in bushes. Some plants are *solid* — bamboo, cactus, huge mushroom caps — which made the ground search stop at the top of the plant and call it the floor, so ash landed on bamboo and half a mushroom turned to dirt; `isStanding` names them and they are left whole. Hanging plants need an anchor, not a footing, and `HangingPlants` prunes the ones left adrift — but only inside the chunk pipeline; whole-shape placements build *after* every footprint chunk's pipeline has finished, so `StructureField.clear` prunes the strands its own removals orphan, reading across borders as only it may. One more rule, learned from houses standing in rivers: **water stops the downward ground walk** in both `ChunkContext.groundY` and `StructureField.groundY`, so a shallow river's "ground" is its surface and `isFluidColumn` is true over *any* water — before that fix only water deeper than the scan band counted, and everything from road paving to house footprints treated riverbeds as land. Whole-footprint features must test every column, not just their centre.

Two rules about removal, both learned from craters. `Blast` takes whatever was standing on a column an impact carved — both crater passes cut downwards only, so a crater under a forest left the forest floating over the hole. And huge crater sites are gated on `LandLookup` — three quarters of the first ones anybody walked to were at sea, where fluid columns are skipped and nothing is carved at all — plus a corruption-field test, so the biggest hole in the ground lands in country that already looks hit. `LandLookup` is an interface rather than a direct biome call for a specific reason: naming `org.bukkit.block.Biome` makes a class untestable — Mockito cannot even mock it — so the Bukkit call is confined to one factory method and everything that *decides* stays testable. Prefer that pattern for any future terrain question.

`WorldEngineFactory` wires the `ChunkProcessor` pipeline and the transformer list; new systems go there. `HangingPlants` must stay **last** in that pipeline: it cleans up after anything that removes a block, so it has to see the finished chunk. A sweep at the end catches strippers nobody has written yet, which a check bolted onto each removing pass cannot. `AbstractBiomeTransformer` holds the shared pass order — dry beds, undergrowth, ash mantle, then trees and craters — so a biome group needs only its biome set, its `AshPalette`, and the odd flag. The shared ash carpet across all palettes is what makes it one event; the materials underneath keep biome identity.

`CorruptionStatisticsTest` asserts observable coverage, not wiring. Both historical failures shipped looking correct and were only catchable by measuring how much of the world actually changed. Keep that test honest when tuning.

Unit tests cannot touch `org.bukkit.block.Biome` — its constants initialise from the server registry, so loading the class outside a running server throws. Test biome-dependent code through seams that do not reference `Biome`, or leave it to runtime.

**Command declaration**: CommandAPI is initialized in `onLoad()`/`onEnable()` and registers commands programmatically (extend cw-commons' `BaseCommand`, then call `.register()` in `onEnable()`). Adding a matching entry under `commands:` in `plugin.yml` makes Bukkit register the same command a second time, which CommandAPI flags at startup with a "Plugin command ... is registered by Bukkit" warning. `permissions:` entries are unaffected and still required.

**Versioning logic** (in `build.gradle.kts`):

- No `-Pver` supplied -> `yyMMdd-HHmm-SNAPSHOT`
- `-Pver=vX.Y.Z-RC-N` -> `X.Y.Z-RC-N-SNAPSHOT`
- `-Pver=vX.Y.Z` -> `X.Y.Z` (stable release)

**CI workflows** (`.github/workflows/`):

- `pr.yml`: builds and tests on Ubuntu + Windows for PRs and merge queue
- `main.yml`: builds, tests, and uploads a snapshot artifact on push to `main`
- `tag.yml`: builds tagged versions and creates a draft GitHub release
- `codeql.yml`: CodeQL analysis for Java and Actions

**Test suites**: `test` contains isolated unit tests and may mock external boundaries.
`integrationTest` exercises the pinned cw-commons dependency directly, including configuration
loading and SQLite persistence. Integration tests use JUnit temporary directories for generated
files. Run this suite separately with `./gradlew integrationTest`.

## Agent instructions

1. Canonical skills live in `.agents/skills/`. The `.claude/skills/` directory is a generated mirror.
2. `CLAUDE.md` is a generated copy of this `AGENTS.md`.
3. Do not edit or create `CLAUDE.md` or files under `.claude/skills/`. Claude hooks configured in `.claude/settings.json` synchronize these mirrors on `SessionStart` and `PostToolUse`.
